# Contributing

Thanks for your interest in CodeRoom AI.

## Before opening a pull request

1. Open an issue describing the bug or proposed change.
2. Keep changes focused and explain the user impact.
3. Never commit secrets, `.env` files, generated build output, or `node_modules`.
4. Update the README when setup steps, environment variables, or user-facing behaviour changes.
5. Include reproduction steps for bug fixes and tests when practical.

## Local development

Follow the setup instructions in [README.md](README.md). Run the client production build and manually verify the affected flow before submitting a pull request. Automated test coverage is a work in progress; do not describe untested behaviour as verified.

## Pull request checklist

- [ ] The change has a clear purpose and description.
- [ ] No credentials or personal data are included.
- [ ] Relevant setup or documentation is updated.
- [ ] The affected user flow has been tested locally.
